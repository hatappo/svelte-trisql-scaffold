# svelte-trisql-scaffold

A demo and, eventually, a scaffolder: SvelteKit 3 Remote Functions + [trisql](https://github.com/hatappo/trisql), with types flowing from the database schema through 2-way SQL templates to the form.

Status: the toolchain is verified end to end and a first scaffolder generates remote functions and pages per table.

## What is verified

- `.remote.ts` files import generated `.sql` queries (`#lib/sql/public/users/crud/index.ts`) and expose them as `query` / `form` / `command` remote functions.
- `tsc --runExternalCode` on TypeScript 7.1 types the `.sql` imports through trisql's content mapper: zero errors.
- `svelte-check` on TypeScript 6 types the same imports through trisql's generated `.d.sql.ts` declaration files: zero errors.
- `vite build` and `vite dev` work with `trisql/vite`; `/users` renders rows from an embedded PGlite with no database server.

## Scaffold

```sh
node scripts/scaffold.ts [--force] [table ...]
```

For every table with a single-column primary key it writes, from the schema in `trisql.json`:

- `src/lib/sql/<schema>/<table>/crud/` (the same as `npx trisql generate`)
- `src/lib/<table>.remote.ts` with `list`, `get`, `create` (form), `update` (form) and `delete` (command), each validated by a Valibot schema derived from the columns
- `src/routes/<table>/+page.svelte` (list and create form) and `src/routes/<table>/[id]/+page.svelte` (edit form and delete)

The `.remote.ts` and route files are yours after generation; existing files are kept unless `--force` is given. The `crud/` directory stays generated.

Column to form mapping: enums become `<select>`, booleans checkboxes, `int2` / `int4` / floats number inputs, `int8` / `numeric` text validated as decimals, dates and timestamps date / datetime-local inputs, JSON a text field validated as JSON, everything else text. Array columns are left out of forms. Nullable and defaulted columns are optional; empty inputs become `undefined`, which trisql renders as `DEFAULT`.

Known gap: a generated `update-by-*` template types its `updates` values from one sample column, so a table whose updatable columns mix strings and booleans gets a cast in the scaffolded `update` (tracked as trisql#4).

## Layout

```text
db/schema.sql                      the schema, applied to PGlite at startup (and used by trisql for typing)
trisql.json                        { "schema": ["db/schema.sql"], "generate": { "out": "src/lib/sql" } }
src/lib/sql/<schema>/<table>/crud/ generated by `npx trisql generate` (templates, index.ts, *.d.sql.ts)
src/lib/server/db.ts               the PGlite instance (server only)
src/lib/<table>.remote.ts          generated remote functions on top of the queries
src/routes/<table>/                 generated list, create, edit and delete pages
scripts/scaffold.ts                the scaffolder
```

## Two TypeScripts

Svelte tooling (`svelte-check`, the Svelte language server) runs on TypeScript 6, which has no content mappers. The project therefore keeps `typescript@6` as the main `typescript` and adds TypeScript 7.1 under the alias `typescript7`:

```sh
npm run check       # svelte-check (TypeScript 6), uses the .d.sql.ts files
npm run typecheck   # tsc 7.1 --runExternalCode, uses the content mapper
```

After changing `db/schema.sql` or a `.sql` template, run `npx trisql generate` to refresh the templates and declaration files.

## Run

```sh
npm install
npx trisql generate
npm run dev
```

Open `/users`.
