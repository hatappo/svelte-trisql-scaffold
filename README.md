# svelte-trisql-scaffold

A demo and, eventually, a scaffolder: SvelteKit 3 Remote Functions + [trisql](https://github.com/hatappo/trisql), with types flowing from the database schema through 2-way SQL templates to the form.

Status: the toolchain is verified end to end; the scaffolder is next.

## What is verified

- `.remote.ts` files import generated `.sql` queries (`#lib/sql/public/users/crud/index.ts`) and expose them as `query` / `form` / `command` remote functions.
- `tsc --runExternalCode` on TypeScript 7.1 types the `.sql` imports through trisql's content mapper: zero errors.
- `svelte-check` on TypeScript 6 types the same imports through trisql's generated `.d.sql.ts` declaration files: zero errors.
- `vite build` and `vite dev` work with `trisql/vite`; `/users` renders rows from an embedded PGlite with no database server.

## Layout

```text
db/schema.sql                      the schema, applied to PGlite at startup (and used by trisql for typing)
trisql.json                        { "schema": ["db/schema.sql"], "generate": { "out": "src/lib/sql" } }
src/lib/sql/<schema>/<table>/crud/ generated by `npx trisql generate` (templates, index.ts, *.d.sql.ts)
src/lib/server/db.ts               the PGlite instance (server only)
src/lib/users.remote.ts            remote functions built on the generated queries
src/routes/users/+page.svelte      list, create, delete
```

## Two TypeScripts

Svelte tooling (`svelte-check`, the Svelte language server) runs on TypeScript 6, which has no content mappers. The project therefore keeps `typescript@6` as the main `typescript` and adds TypeScript 7.1 under the alias `typescript7`:

```sh
npm run check       # svelte-check (TypeScript 6), uses the .d.sql.ts files
npm run typecheck   # tsc 7.1 --runExternalCode, uses the content mapper
```

After changing `db/schema.sql` or a `.sql` template, run `npx trisql generate` to refresh the templates and declaration files.

## Run

```sh
npm install
npx trisql generate
npm run dev
```

Open `/users`.
